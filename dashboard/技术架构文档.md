## 1. 系统概述

### 1.1 定位

交通信控平台 是一个**物理层无关**的交通信号控制系统前端平台，通过标准化接口与各种外部环境进行交互，包括：
- **训练框架**（如 LibSignal、SUMO-PPO-GNN）
- **交管系统**（如 SCATS、SCOOT、真实交管平台）
- **数据库系统**（如 TDengine、InfluxDB 时序数据库）
- **其他外部系统**（气象、事件、监控等）

系统设计遵循**前后端分离**和**适配器模式**，确保核心功能与具体物理层实现解耦。

### 1.2 技术栈

**后端**：
- Python 3.8+
- Flask 2.x (Web 框架)
- SUMO (交通仿真器)

**前端**：
- 原生 JavaScript (ES6+)
- HTML5 + CSS3
- Canvas API (可视化渲染)

**数据格式**：
- JSON (API 通信)
- YAML (配置文件)
- XML (SUMO 网络数据)

## 2. 核心设计理念

### 2.1 分层架构

```
┌─────────────────────────────────────────────────┐
│              Web Frontend (Browser)             │
│  - Visualization  - Control Panel  - Tools      │
└────────────────────┬────────────────────────────┘
                     │ RESTful API (JSON)
┌────────────────────┴────────────────────────────┐
│           Dashboard Backend (Flask)             │
│  - API Layer  - Business Logic  - State Mgmt    │
└────────────────────┬────────────────────────────┘
                     │ Standard Interface
┌────────────────────┴────────────────────────────┐
│              Adapter Layer (Pluggable)          │
│  - Config Converter  - Data Transformer         │
└────────────────────┬────────────────────────────┘
                     │ Physical Layer Interface
┌────────────────────┴────────────────────────────┐
│               Physical Layer                    │
│  - Training Frameworks  - Traffic Systems       │
│  - Database Systems     - Other External Sys    │
└─────────────────────────────────────────────────┘
```

### 2.2 设计原则

1. **接口标准化**：Dashboard 定义标准接口，不依赖特定物理层组件的实现细节
2. **适配器解耦**：通过 Adapter 层隔离物理层差异，便于切换和扩展不同的训练框架、交管系统、数据库
3. **状态独立性**：Dashboard 维护自己的状态管理，不直接依赖物理层状态
4. **配置驱动**：所有可变行为通过配置文件控制，避免硬编码
5. **异步非阻塞**：长时间任务（训练、仿真、数据记录）在后台线程运行，不阻塞 UI
6. **多源兼容**：支持同时接入多个物理层组件（如训练框架 + 数据库），互不干扰

### 3.2 核心组件

#### 3.2.1 Frontend Components

- **Network View**：地图网络可视化，显示路口、道路及实时状态
- **Realtime Monitor**：实时监控仿真状态、交通流量、性能指标
- **Training Tool**：模型训练管理界面
- **Comparison Tool**：多模型对比实验工具
- **Models Manager**：模型版本管理与评估
- **Traffic Data Tool**：交通数据查询与分析界面，集成时序数据库前端

#### 3.2.2 Backend Controllers

- **SimulationManager**：仿真进程生命周期管理
- **JunctionManager**：路口智能体状态管理
- **TrainingController**：训练任务调度与监控
- **ComparisonController**：对比实验执行与结果分析
- **ModelsController**：模型存储与元数据管理
- **TrafficDataController**：交通数据库接入与查询管理

#### 3.2.3 Integration Layer

- **DashboardController**：集成仿真、智能体、前端通信的中央控制器
- **StandardInterface**：定义与训练器交互的标准接口
- **Adapter**：实现特定训练框架的适配逻辑

## 4. 标准接口定义

### 4.1 StandardArgs

训练器无关的标准化参数对象。

```python
class StandardArgs:
    """
    标准化参数接口
    
    所有训练器适配器必须能够接受此标准参数格式
    """
    # 基本配置
    tsc: str           # 算法名称 (e.g., 'colight', 'maxpressure')
    sim: str           # 场景名称 (e.g., '81', 'hangzhou')
    mode: str          # 运行模式 ('train', 'test', 'inference')
    
    # 仿真参数
    nogui: bool        # 是否禁用 GUI
    enable_db: bool    # 是否启用数据库记录
    simlen: int        # 仿真时长/步数
    step_delay: float  # 步进延迟（秒）
    
    # 交通参数
    demand: str        # 交通需求类型 ('onfly', 'fixed', 'json_flow')
    scale: float       # 交通流量倍数
    gmin: int          # 最小绿灯时长
    r: int             # 红灯时长
    y: int             # 黄灯时长
    
    # 其他参数
    port: int          # 端口号
    interface: str     # 接口类型 ('libsumo', 'traci')
```

### 4.2 StandardSimulation

仿真控制的标准接口。

```python
class StandardSimulation(ABC):
    """
    仿真控制标准接口
    
    适配器必须实现此接口以提供仿真控制能力
    """
    
    @abstractmethod
    def initialize(self) -> bool:
        """初始化仿真环境"""
        pass
    
    @abstractmethod
    def start(self) -> bool:
        """启动仿真"""
        pass
    
    @abstractmethod
    def step(self) -> Dict[str, Any]:
        """执行一步仿真，返回当前状态"""
        pass
    
    @abstractmethod
    def stop(self) -> bool:
        """停止仿真"""
        pass
    
    @abstractmethod
    def reset(self) -> bool:
        """重置仿真"""
        pass
    
    @abstractmethod
    def get_current_state(self) -> Dict[str, Any]:
        """获取当前仿真状态"""
        pass
    
    @abstractmethod
    def current_time(self) -> float:
        """获取当前仿真时间"""
        pass
```

### 4.3 StandardSolver

智能体求解器的标准接口。

```python
class StandardSolver(ABC):
    """
    智能体求解器标准接口
    
    提供信号控制决策能力
    """
    
    @abstractmethod
    def get_action(self, observation: Any, test: bool = True) -> Any:
        """根据观察获取动作"""
        pass
    
    @abstractmethod
    def update_policy(self, *args, **kwargs) -> None:
        """更新策略（训练模式）"""
        pass
    
    @abstractmethod
    def load_model(self, path: str, epoch: int = None) -> bool:
        """加载预训练模型"""
        pass
    
    @abstractmethod
    def save_model(self, path: str, epoch: int = None) -> bool:
        """保存模型"""
        pass
```

### 4.4 StandardInterface

完整的训练器交互接口。

```python
class StandardInterface(ABC):
    """
    训练器交互标准接口
    
    整合仿真控制、智能体管理、数据获取
    """
    
    @abstractmethod
    def get_netdata(self) -> Dict[str, Any]:
        """
        获取网络数据
        
        Returns:
            {
                'inter': {intersection_id: {...}},
                'lane': {lane_id: {...}},
                'edge': {edge_id: {...}},
                'node': {node_id: {...}}
            }
        """
        pass
    
    @abstractmethod
    def signal_update(self) -> None:
        """执行信号灯更新（智能体决策）"""
        pass
    
    @abstractmethod
    def update_subscription_cache(self) -> None:
        """更新订阅数据缓存（交通状态）"""
        pass
    
    @property
    @abstractmethod
    def subscription_cache(self) -> Dict[str, Any]:
        """
        获取订阅数据缓存
        
        Returns:
            {
                'lane_data': {lane_id: {
                    'vehicle_number': int,
                    'mean_speed': float,
                    'occupancy': float,
                    'halting_number': int
                }},
                'traffic_light_data': {tl_id: {
                    'phase_state': str,
                    'phase_duration': float,
                    'phase_index': int
                }}
            }
        """
        pass
```

**训练流程**：

1. 接收前端配置
2. 生成训练器所需的配置文件（通过 Adapter）
3. 在后台线程启动训练进程
4. 实时解析训练输出，提取进度和指标
5. 通过轮询接口向前端推送状态

            {
                'enabled': bool,
                'type': str,  # 'tdengine', 'influxdb', etc.
                'host': str,
                'port': int,
                'database': str
            }
        """
        
    def get_database_frontend_url(self) -> str:
        """
        获取数据库前端访问地址
        
        Returns:
            str: 数据库 Web UI 的 URL (e.g., 'http://localhost:6041')
        """
        
    def query_traffic_data(self, query_params: Dict[str, Any]) -> Dict[str, Any]:
        """
        查询交通数据
        
        Args:
            query_params: 查询参数
                - junction_id: 路口ID
                - start_time: 开始时间
                - end_time: 结束时间
                - metrics: 指标列表
                
        Returns:
            {
                'success': bool,
                'data': [
                    {
                        'timestamp': int,
                        'junction_id': str,
                        'vehicle_count': int,
                        'avg_speed': float,
                        ...
                    }
                ]
            }
        """
        
    def enable_recording(self, config: Dict[str, Any]) -> Dict[str, Any]:
        """
        启用交通数据记录
        
        Args:
            config: 记录配置
                - record_interval: 记录间隔（秒）
                - metrics: 要记录的指标
                
        Returns:
            {'success': bool, 'message': str}
        """
        
    def disable_recording(self) -> Dict[str, Any]:
        """停止交通数据记录"""
```

**应用场景**：

1. **仿真数据记录**：将仿真过程中的交通数据持久化到时序数据库
2. **真实系统接入**：部署到真实交管系统时，记录实际交通数据
3. **数据分析**：通过数据库前端（如 TDengine 的 Grafana）进行可视化分析
4. **长期评估**：对比不同时间段、不同算法的交通控制效果

**数据库支持**：

- **TDengine**：高性能时序数据库，适用于物联网场景
- **InfluxDB**：广泛使用的时序数据库
- **TimescaleDB**：基于 PostgreSQL 的时序数据库扩展
- **自定义**：通过 Adapter 可接入其他数据库系统

## 8. 扩展性设计

### 8.1 物理层（Physical Layer）设计

物理层是平台的最底层，代表所有可接入的外部环境和系统。通过标准化的 Adapter 接口，平台可以灵活接入各种物理层组件：

#### 8.1.1 物理层组件分类

**1. 训练框架（Training Frameworks）**
- **LibSignal**：交通信号控制研究框架
- **SUMO-PPO-GNN**：基于图神经网络的 PPO 算法
- **Ray RLlib**：可扩展的强化学习库
- **Custom Frameworks**：自定义训练框架

**2. 交通控制系统（Traffic Control Systems）**
- **Real Traffic Systems**：真实交管系统接入
- **SCATS**：Sydney Coordinated Adaptive Traffic System
- **SCOOT**：Split Cycle Offset Optimisation Technique
- **SUMO Simulator**：开源交通仿真器
- **Vissim**：商业交通仿真软件

**3. 数据库系统（Database Systems）**
- **TDengine**：高性能时序数据库
- **InfluxDB**：广泛使用的时序数据库
- **TimescaleDB**：PostgreSQL 扩展的时序数据库
- **Prometheus**：监控和时序数据存储
- **Custom Databases**：自定义数据存储方案

**4. 其他外部系统**
- **气象数据源**：实时天气信息
- **事件管理系统**：交通事故、施工等事件
- **地图服务**：第三方地图 API
- **视频监控**：交通摄像头数据流

#### 8.1.2 物理层接入原则

1. **标准化接口**：所有物理层组件通过 Adapter 接入
2. **热插拔**：支持动态切换不同的物理层组件
3. **隔离性**：物理层故障不影响平台核心功能
4. **可配置**：通过配置文件控制物理层接入
5. **监控告警**：实时监控物理层连接状态

                - timestamp: 时间戳
                - vehicle_count: 车辆数
                - ...
        """
        # 转换为 Prometheus 格式
        prometheus_metrics = self._convert_to_prometheus(metrics)
        # 推送到 Pushgateway
        return self._push_metrics(prometheus_metrics)
    
    def query_metrics(self, query: str, start: int, end: int) -> List[Dict]:
        """
        查询指标数据
        
        Args:
            query: PromQL 查询语句
            start: 开始时间
            end: 结束时间
        """
        result = self.client.query_range(
            query=query,
            start=start,
            end=end
        )
        return self._parse_result(result)
    
    def get_frontend_url(self) -> str:
        """获取 Prometheus Web UI 地址"""
        return f"http://{self.host}:{self.port}"
```

## 附录

### A. 术语表

- **TSC (Traffic Signal Control)**：交通信号控制
- **Junction**：路口，交通信号灯控制的交叉路口
- **Lane**：车道，道路的基本单元
- **Phase**：相位，信号灯的一种状态（如东西直行、南北左转等）
- **Adapter**：适配器，连接 Dashboard 和物理层的中间层
- **Physical Layer**：物理层，所有可接入的外部环境和系统（训练框架、交管系统、数据库等）
- **Baseline**：基准算法，用于对比的传统算法（如 FixedTime、MaxPressure）
- **Episode**：训练轮次，一次完整的仿真运行
- **Epoch**：训练周期，多个 episode 的集合
- **Time Series Database**：时序数据库，专门用于存储和查询时间序列数据的数据库系统
- **TDengine**：高性能时序数据库，适用于物联网和工业场景
- **SCATS**：悉尼协调自适应交通系统，一种实时交通信号控制系统
- **SCOOT**：英国开发的交通信号优化系统
